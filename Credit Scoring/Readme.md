## **Название проекта:**

**Credit Scoring Optimization: How ML can save $1.4M in bad debt**

---

## **Цель проекта:**

Разработать модель для предсказания вероятности одобрения кредита клиенту на основе исторических данных. Цель — показать умение полностью пройти цикл ML-проекта: от EDA до интерпретации модели и презентации бизнес-результатов.

---

🏦 Credit Scoring Model (XGBoost) 📊 Результаты:
Модель: XGBoost + Hyperparameter Tuning.

ROC-AUC: 0.87

Бизнес-эффект: Использование модели увеличивает чистую прибыль портфеля на $7.48 млн (на каждые 30к заявок) по сравнению со стратегией массового одобрения.

Оптимальный порог: 0.735 (выбран на основе максимизации P&L).

🛠 Стек:
Python (Pandas, Scikit-learn, XGBoost).

Interpretability: SHAP (Kernel & Tree Explainers).

Scaling: StandardScaler.

🧠 Ключевые инсайты (SHAP):
Revolving Utilization — самый мощный фактор. Перегрузка кредитных карт — главный сигнал дефолта.

Age — имеет нелинейное влияние; молодые заемщики в среднем более рискованны.

Monthly Income — имеет низкую предсказательную силу сам по себе без учета долговой нагрузки.

## **Этапы реализации:**


### **1. Сбор данных**

* Источник: Kaggle, запрос `Credit Scoring`:

  * [Give Me Some Credit](https://www.kaggle.com/c/GiveMeSomeCredit)
* Состав данных: демография клиента, финансовые показатели, история кредитов, платежи, задолженности.

---

### **2. Исследовательский анализ данных (EDA)**

* Основные шаги:

  * Изучение структуры данных: типы колонок, пропуски.
  * Анализ распределений числовых и категориальных признаков.
  * Корреляционный анализ.
  * Визуализация выбросов и аномалий.
  * Проверка баланса классов (отказ/одобрение кредита).
* Библиотеки: `pandas`, `numpy`, `matplotlib`, `seaborn`, `plotly` (для интерактивных графиков).

---

### **3. Подготовка данных**

* Обработка пропусков: среднее/медиана для числовых, мода для категориальных.
* Кодирование категориальных признаков: `OneHotEncoder` или `Target Encoding`.
* Масштабирование числовых признаков: `StandardScaler` или `MinMaxScaler`.
* Генерация новых признаков (feature engineering):

  * Долг/доход, средний платеж, кредитная нагрузка.
  * История просрочек.
* Разделение данных на train/test (например, 80/20).

---

### **4. Базовая модель**

* Логистическая регрессия как бейзлайн. (для нее со скейлером, для деревьев -без)
* Метрики:

  * ROC AUC
  * Accuracy
  * Precision/Recall
  * F1-score
* Библиотеки: `scikit-learn`

---

### **5. Продвинутые модели**

* Случайный лес (`RandomForestClassifier`)
* Градиентный бустинг (`XGBoost`, `LightGBM` или `CatBoost`)
* KNN (`KNeighborsClassifier`) — для демонстрации, обычно хуже на больших данных
* Сравнение моделей по метрикам.
* Подбор гиперпараметров: `GridSearchCV` или `RandomizedSearchCV`.

---

### **6. Интерпретация модели**

* Feature importance (для случайного леса и градиентного бустинга)
* SHAP или LIME для объяснения предсказаний модели
* Выводы о ключевых факторах, влияющих на решение по кредиту.
* Библиотеки: `shap`, `lime`

---

### **7. Бизнес-практика**

* АВ тест для первой модели (логистической регрессии):

  * Разделение клиентов на 2 группы.
  * Сравнение предложений кредита и одобрений.
* Подготовка краткого отчета для менеджеров/инвесторов:

  * Ключевые метрики
  * Основные факторы риска
  * Рекомендации по принятому кредитному решению

---

### **8. Презентация**

* В виде Jupyter Notebook с графиками и пояснениями.
* Можно добавить визуализацию:

  * ROC-кривые
  * Feature importance
  * Сводная таблица по метрикам всех моделей
* Для портфолио — добавить Markdown с объяснением бизнес-контекста.

## **Критерии завершения**

1. Проведен полный EDA.
2. Данные подготовлены для моделей.
3. Базовая модель (логистическая регрессия) построена и оценена.
4. Использованы 2–3 продвинутые модели и выбрана лучшая.
5. Сделан анализ важности признаков.
6. Написан отчет с визуализациями и бизнес-выводами.
7. Код чистый, понятный, снабжен комментариями и оформлен в портфолио-ready ноутбук.
