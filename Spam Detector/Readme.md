# 📩 SMS Spam Filter: Naive Bayes from Scratch

Проект по разработке классификатора спам-сообщений на основе **Наивного Байесовского классификатора (NB)**. Основной акцент сделан на реализации математики алгоритма «с нуля», глубокой предобработке текста и оптимизации бизнес-метрик для минимизации ложных срабатываний.

## 🎯 Цель проекта
Показать умение работать с неструктурированными текстовыми данными (NLP) и реализовывать вероятностные модели без использования готовых библиотек машинного обучения (за исключением этапа сравнения).

## 🛠 Стек технологий
*   **Язык:** Python 3.10+
*   **Библиотеки:** Pandas, NumPy, NLTK (обработка текста), Matplotlib/Seaborn (визуализация).
*   **Инструменты:** Scikit-learn (только для валидации и сравнения результатов).

## 📈 Ключевые этапы реализации

### 1. Предобработка текста (NLP Pipeline)
Для очистки данных была выстроена цепочка преобразований:
*   Токенизация и приведение к нижнему регистру.
*   Удаление стоп-слов и пунктуации.
*   **Стемминг (Porter Stemmer):** приведение слов к их корню (например, `winning` -> `win`).
*   Обработка спец-символов (валюты, спец-знаки), характерных для спама.

### 2. Математическая модель
Реализован класс `NaiveBayesClassifier`, использующий:
*   **Априорные вероятности** классов.
*   **Вероятности правдоподобия (Likelihood)** для каждого слова.
*   **Сглаживание Лапласа ($\alpha=1$):** для решения проблемы нулевых вероятностей новых слов.
*   **Логарифмирование вероятностей:** для предотвращения арифметического переполнения (underflow) при работе с длинными текстами.

### 3. Сравнение результатов
Модель, написанная с нуля, показала результаты, практически идентичные библиотечному решению:
*   **Accuracy (Моя модель):** 97.25%
*   **Accuracy (Scikit-learn):** 98.09%

## 🔍 Интерпретация и "Триггеры" спама
Анализ показал, что модель корректно выделила ключевые маркеры спама. Топ-5 индикаторов по весам:
1. `claim` (претендовать/получить)
2. `prize` (приз)
3. `tone` (рингтон/мелодия)
4. `å` (спец-символ кодировки)
5. `award` (награда)

## ⚖️ Оптимизация бизнес-порога (Threshold Tuning)
В задачах фильтрации спама **False Positive (ошибочное занесение важного письма в спам)** гораздо критичнее, чем пропуск спам-сообщения. 

Мною был проведен анализ изменения порога принятия решения:

| Threshold | FP (Ошибка на Ham) | FN (Пропуск Спама) | Комментарий |
|-----------|--------------------|--------------------|-------------|
| 0         | 19                 | 4                  | Стандартный порог |
| **7**     | **0**              | **15**             | **Выбранный порог (Безопасный)** |
| 20        | 0                  | 38                 | Слишком консервативный |

**Вывод:** При пороге **7.0** модель полностью исключает риск блокировки нормальных писем (FP=0), сохраняя при этом высокую эффективность фильтрации.
